常见问题

报价前需要给什么。

多久能开始？

边界清楚的小任务，通常只需要一个脱敏样例、期望输出、失败命令或当前流程，就能判断是否可报价。

能看私有仓库吗？

可以，但必须是你有权授权的仓库；公开描述里不要贴密码、token、生产数据或客户隐私。

可以先做诊断吗？

可以。小型 audit 可以先给出问题清单、下一步补丁范围、缺失测试和验证命令。

什么样的需求最好报价？

有假数据样例、期望输出、失败命令和完成标准的需求，通常能更快判断价格和交付范围。

交付物有什么？

按任务交付脚本、补丁、review 报告或原型，并附 README、运行方式、验证结果和未测边界。

哪些材料不要发？

不要发密码、API key、付款信息、客户原始数据、生产数据库、隐私截图或你无权分享的文件。

付款信息怎么处理？

付款和平台规则不放在公开需求里处理。公开 issue 只写范围、样例和验收标准。

报价入口

提交公开、脱敏的范围说明。

用 GitHub issue form 提交 repo 链接、失败命令、输入输出样例和预算范围。 不要提交密码、token、客户隐私数据、付款信息、生产密钥，或任何你无权分享的文件。
